# Request 0 — First shop

Build me a little shop called DispatchLedger. Show the products and prices, let someone add things to a basket and place an order, and give me a page where I can see orders. Use the sample products. No real payments yet. Keep the orders if I restart it, and give me buttons I can actually try.

## What I need

**Sample data.** When the shop starts with empty storage it loads three products (prices in
pence):

| id | name | price |
| --- | --- | --- |
| `tea` | Breakfast Tea | 450 |
| `mug` | Enamel Mug | 1250 |
| `apron` | Canvas Apron | 2200 |

Two example buyers you can use in demos: Ada Lovelace `ada@example.test` and Grace Hopper
`grace@example.test`.

**Pages** (plain HTML, real forms and buttons):

- `GET /` — the shop: every product with its name and price, a basket people can add products
  to, its total, and a way to place the order with a name and email address.
- `GET /orders` — every order (id, customer, total), each linking to `GET /orders/{id}`, which
  shows that order's items and total.
- Amounts on pages are shown as `£` followed by pounds and two-digit pence, no thousands
  separator: 450 → `£4.50`, 123450 → `£1234.50`.

**Products.**

- `GET /api/products` → `{"products": [{"id": "tea", "name": "Breakfast Tea", "price": 450}, ...]}`
  sorted by `id`. `GET /api/products/{id}` → one product, unknown → `404 not_found`.
- `POST /api/products` with `{"id": "scarf", "name": "Wool Scarf", "price": 1800}` adds a product →
  `201` with the product. `id` matches `[a-z0-9-]{1,40}`, `name` is a non-empty string of at
  most 100 characters, `price` an integer ≥ 0; otherwise `422 invalid_request`. An existing id →
  `409 conflict`.

**Basket and checkout.** Both take a list of lines `{"product_id": "tea", "quantity": 2}`.

- `POST /api/quote` with `{"items": [...]}` → `200` with the basket:
  `{"items": [{"product_id": "tea", "name": "Breakfast Tea", "unit_price": 450, "quantity": 2, "line_total": 900}], "total": 900}`
  (lines in the order given). Nothing is stored.
- `POST /api/orders` with
  `{"customer": {"name": "Ada Lovelace", "email": "ada@example.test"}, "items": [...]}` places
  the order → `201` with the order:

```json
{"id": "<generated by the shop>", "created_at": "2026-03-02T09:00:00Z",
 "customer": {"name": "Ada Lovelace", "email": "ada@example.test"},
 "items": [{"product_id": "tea", "name": "Breakfast Tea", "unit_price": 450,
            "quantity": 2, "line_total": 900}],
 "total": 900}
```

- `created_at` is the current time (see `DISPATCHLEDGER_CLOCK_FILE`) at checkout.
- `GET /api/orders` → `{"orders": [...]}` oldest first; `GET /api/orders/{id}` → one order,
  unknown → `404 not_found`. Orders may carry more fields than shown; these must be present.

**Input rules** (quote and checkout, from the public data pack):

- `items` must be a non-empty list → otherwise `422 invalid_request`; the same product twice in
  one list → `422 invalid_request`.
- Quantities are positive integers: a quantity that is not a JSON integer ≥ 1 (0, negative,
  decimal, string, boolean, missing) → `422 invalid_quantity`.
- Product ids must exist: an unknown `product_id` → `422 unknown_product`.
- Checkout also needs `customer.name` (non-empty string) and `customer.email` (a string
  containing `@`) → otherwise `422 invalid_request`.
- A rejected request stores nothing.

Orders and added products survive a restart of the web app.
